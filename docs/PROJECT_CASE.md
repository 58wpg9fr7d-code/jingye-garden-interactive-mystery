# 作品集案例：把复杂剧本组织成可执行的互动产品

## 一句话

独立设计并实现一套科幻多人推理互动产品，并进一步抽象出“谜构 ScriptLab”创作一致性工作台：将复杂世界观、角色关系、行动链和线索指向转化为可体验、可检查的产品工作流。

## 问题

原始内容包含多层世界、角色秘密、案发行动链和多个结局。单纯把内容放进长文档，玩家很难知道“现在该看什么、哪些信息还不能看、线索之间如何关联”，主持人也难以稳定控制节奏。

## 方案

- 用“角色—阶段—内容”三层结构管理信息
- 用三幕与阶段解锁控制认知负荷和剧透风险
- 用角色卡、证物、时间线、线索板和红线把抽象关系变成可操作的界面
- 用线索卡 MVP 模拟 DM 控制的解锁与发放机制
- 用四结局把玩家的推理结果转成有代价的产品选择
- 将作者高频检查任务拆成关系网络、时间线、线索平衡和角色模拟四个工作台模块
- 用规则驱动角色回复先验证交互和一致性边界，明确后续再接入大模型

## 实现

- 以原生 HTML/CSS/JavaScript 完成两个无依赖静态 MVP
- 侦探卷宗实现弹窗、点击高亮关联、时间线展开、真相显隐等交互
- 线索卡实现阶段切换、随机抽卡、已抽收藏和未解锁占位保护
- 整理角色本、案件文本、视觉资产和设计评审材料，形成可复现仓库
- 新版 ScriptLab 提供新增行动、线索和角色提问的可交互验证入口，并附带 PM 作品集页

## 验证

- 静态页面可在本地 HTTP 服务启动并访问
- 关键交互通过代码检查：角色弹窗、线索板、时间线、真相切换、阶段抽卡
- 页面不依赖 API Key 和后端服务，适合面试官直接打开体验
- 新版 Vercel 工作台、手机端剧情体验、终局谜题入口均已核验返回 200；本地源码构建通过
- 手机端剧情的角色解锁、线索推进等状态仍是前端演示逻辑，不应写成实时多人或 AI 已上线

## 个人贡献

从世界观组织、角色与权限分级、机制设计、信息架构、流程与交互，到视觉素材整理、网页实现和部署准备，均由本人独立完成；AI 仅用于辅助开发和资料整理。
